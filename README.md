# 配膳お知らせアプリ

設置時間の指定分数前になると、このアプリを登録した人全員のスマホのホーム画面に自動でお知らせが届くアプリです。
「配達完了にする」を押したとき、「＋ 追加」で新しい予定を登録したときも、同様に全員へ即座に通知が届きます。

中身のスケジュールは `2026配膳発注システム.xlsx` の「発注・配達管理」シート（77件）をそのまま取り込み済みです。

## 公開URL（公開済み）

**https://keitakudo-debug.github.io/haizen-oshirase/**

このURLをスマホのブラウザで開けばそのまま使えます。GitHub Pages（無料）で公開済みなので、追加のセットアップは不要です。

管理用リポジトリ: https://github.com/keitakudo-debug/haizen-oshirase

### 内容を更新したいとき

このフォルダ内のファイルを編集したあと、フォルダ内で以下を実行すると、数十秒〜数分でサイトに反映されます。

```bash
git add -A
git commit -m "更新内容"
git push
```

## iPhoneでの使い方

1. 上記URLをSafariで開く。
2. 下部の共有ボタン（□に↑）→「ホーム画面に追加」をタップ。
3. **必ずホーム画面に追加したアイコンから** アプリを開く（Safariのタブから直接開くと通知が使えません）。
4. アプリ上部の「通知を有効にする」をタップし、通知を許可する。
5. 右上の ⚙ から「日程（実際の日付）」に、前日・1日目・2日目・3日目の実際のカレンダー日付を入力する。ここを入れないと自動通知は発火しません。
6. 通知タイミング（何分前に知らせるか）も同じ画面で選べます。

## Android（Google Pixelなど）での使い方

1. 上記URLをChromeで開く。
2. 上部の案内バナーに「ホーム画面に追加」ボタンが出たらタップする（出ない場合はChromeメニュー →「アプリをインストール」）。通常のタブのままでも通知は使えますが、ホーム画面に追加した方がバックグラウンドでも届きやすくなります。
3. 「通知を有効にする」をタップし、通知を許可する。
4. iPhoneと同じく、⚙ から日程の実際の日付・通知タイミングを設定する。

## 大事な制約（サーバーなし版の限界）

- アプリを完全に終了（スワイプで消す）すると、その間はタイマーが動かず、通知は届きません。特にiPhoneはこの制約が強く出ます。
- アプリを開いている間・開いた直後は、時間になった予定の通知（見逃した分も含む）がまとめて届きます。こまめに開く運用にしてください。
- Androidはホーム画面に追加してあれば、iPhoneよりバックグラウンドでも通知が届きやすい傾向があります。
- 来年以降も使い回す場合は ⚙ →「全件を『発注済』に戻す」でリセットし、日程の日付だけ入れ直せば再利用できます。

## アプリを閉じてても届く通知（ntfy版・無料・完全自動）

上記の制約を回避して、**アプリを完全に閉じていても・スマホがロックされていても**通知を届ける仕組みです。追加のサーバー構築やアカウント登録・ログインは不要で、[ntfy](https://ntfy.sh)という無料のプッシュ通知専用サービスを使います。GitHubへの手動反映（git push）は一切不要です。

仕組み：以下の3つの操作のタイミングで、アプリがその場で直接ntfyの決められた「トピック（合言葉）」宛てに通知を送信します。スマホのntfyアプリがそのトピックを購読していれば、ホーム画面にプッシュ通知として届きます。

- **新規登録**（「＋ 追加」で予定を保存したとき）→ 即座に通知
- **配達完了**（「配達完了にする」を押したとき）→ 即座に通知
- **設置時間の指定分数前**（⚙で設定した「何分前」）→ 予定を登録・編集した時点、または日程の日付を設定した時点で、ntfyの「予約配信」機能を使ってその時刻ちょうどに届くよう先に予約されます。予約さえ済んでいれば、以降は誰もアプリを開いていなくても指定の時刻に自動で届きます。

### 初回セットアップ（最初の1回だけ）

1. スマホに **「ntfy」というアプリ**（App Store / Google Play、作者: ntfy.sh、無料）をインストールする。
2. アプリを開き「＋」（購読を追加）から、⚙設定画面に表示されているトピック名を入力して購読する。
3. アプリの ⚙ 設定画面で「日程（実際の日付）」と「何分前に知らせるか」を設定する（これでその時点の全予定の予約が作られます）。

これだけで、新規登録・配達完了・時間前リマインドのすべてが登録者全員のホーム画面に自動で届きます。

### 「確認しました」と未確認時の再通知

- 通知の本文は「14時00分　在庫テントへ　アクエリアス500ml 20本・紙コップ 200個」のように、時刻・場所・本数を具体的に表示します（担当者・備考も表示）。
- 通知についている **「確認しました」ボタン**、またはアプリの予定カード／上部の「次の配膳予定」の「確認しました」ボタンで確認できます。確認した人の名前は全員のアプリに「👀 確認済み（名前）」と表示されます。
- ⚙ の「確認しました が押されていないときの再通知」（初期値: 5分前）になっても誰も確認していなければ、もう一度通知します。
- 同じタイミングで、**未確認のときだけ** サブ担当者・拠点端末用トピック（トピック名の末尾に `-sub`）にも「🚨 担当者が未確認です」と届きます。サブ担当者・拠点端末は ⚙ に表示されるサブ用トピック名をntfyアプリで購読してください。
- 確認済み・配達完了・削除になった予定は、まだ届いていない通知・再通知が自動で取り消されます。
- 確認状況は `-ack` で終わるトピックで全端末に共有しています（人が購読する必要はありません）。サーバーは使っていません。

### 使い方・制約

- 予定の時間や日程の日付を後から編集すると、予約済みの通知は新しい時刻のものに自動で置き換わります。
- ntfyの無料版は**最大3日先まで**しか予約できません。3日より先の予定は登録時点では予約されず、3日以内に入ったタイミングで誰かがアプリを開くと自動的に予約されます（多くの場合、日程が近づく数日前には誰かがアプリを開くはずなので実用上は問題ありませんが、絶対に確実というわけではありません）。
- ntfyのトピック名は他人に知られると誰でもその宛先に通知を送れてしまうので、他人と共有しないでください。

### （参考）GitHub Actions + notify-config.json 版（現在は不要）

以前は、GitHub Actionsが5分おきに `notify-config.json` をチェックしてntfyへ送る仕組みを使っていましたが、上記の「アプリがその場で直接予約する」方式に置き換わったため、通常は使う必要がありません。ファイル自体は参考として残っていますが、更新しなくても新しい通知の仕組みは動作します。
