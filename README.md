# 配膳お知らせアプリ

設置時間の指定分数前になると、スマホのホーム画面に自動でお知らせが届くアプリです。
「配達完了にする」を押したときも、完了の通知が届きます。

中身のスケジュールは `2026配膳発注システム.xlsx` の「発注・配達管理」シート（77件）をそのまま取り込み済みです。

## 公開URL（公開済み）

**https://keitakudo-debug.github.io/haizen-oshirase/**

このURLをスマホのブラウザで開けばそのまま使えます。GitHub Pages（無料）で公開済みなので、追加のセットアップは不要です。

管理用リポジトリ: https://github.com/keitakudo-debug/haizen-oshirase

### 内容を更新したいとき

このフォルダ内のファイルを編集したあと、フォルダ内で以下を実行すると、数十秒〜数分でサイトに反映されます。

```bash
git add -A
git commit -m "更新内容"
git push
```

## iPhoneでの使い方

1. 上記URLをSafariで開く。
2. 下部の共有ボタン（□に↑）→「ホーム画面に追加」をタップ。
3. **必ずホーム画面に追加したアイコンから** アプリを開く（Safariのタブから直接開くと通知が使えません）。
4. アプリ上部の「通知を有効にする」をタップし、通知を許可する。
5. 右上の ⚙ から「日程（実際の日付）」に、前日・1日目・2日目・3日目の実際のカレンダー日付を入力する。ここを入れないと自動通知は発火しません。
6. 通知タイミング（何分前に知らせるか）も同じ画面で選べます。

## Android（Google Pixelなど）での使い方

1. 上記URLをChromeで開く。
2. 上部の案内バナーに「ホーム画面に追加」ボタンが出たらタップする（出ない場合はChromeメニュー →「アプリをインストール」）。通常のタブのままでも通知は使えますが、ホーム画面に追加した方がバックグラウンドでも届きやすくなります。
3. 「通知を有効にする」をタップし、通知を許可する。
4. iPhoneと同じく、⚙ から日程の実際の日付・通知タイミングを設定する。

## 大事な制約（サーバーなし版の限界）

- アプリを完全に終了（スワイプで消す）すると、その間はタイマーが動かず、通知は届きません。特にiPhoneはこの制約が強く出ます。
- アプリを開いている間・開いた直後は、時間になった予定の通知（見逃した分も含む）がまとめて届きます。こまめに開く運用にしてください。
- Androidはホーム画面に追加してあれば、iPhoneよりバックグラウンドでも通知が届きやすい傾向があります。
- 来年以降も使い回す場合は ⚙ →「全件を『発注済』に戻す」でリセットし、日程の日付だけ入れ直せば再利用できます。

## アプリを閉じてても届く通知（GitHub Actions版・無料）

上記の制約を回避して、**アプリを完全に閉じていても・スマホがロックされていても**指定分数前に通知を届ける仕組みを追加できます。Cloudflareなど外部サービスは使わず、GitHubの機能（Actions + Issues）と公式GitHubアプリのプッシュ通知だけで完結し、追加費用はかかりません。

仕組み：GitHub Actionsが5分おきにこのリポジトリの `notify-config.json` を見て、指定分数前になった予定を見つけると、`配膳お知らせ通知` というIssueにコメントを投稿します。それをGitHubの公式モバイルアプリが検知して、ホーム画面にプッシュ通知してくれます。

### 初回セットアップ（最初の1回だけ）

1. **GitHubの公式アプリをスマホにインストール**し、このリポジトリ（`keitakudo-debug/haizen-oshirase`）を開いて **Watch**（右上の目のアイコン）→「All Activity」にする。
2. スマホのGitHubアプリの設定（Settings → Notifications）で、**Push通知をON**にする。
3. GitHubのウェブサイトでこのリポジトリの **Settings → Actions → General** を開き、下の方の「Workflow permissions」で **「Read and write permissions」** を選んで保存する（Actionsが通知ログをコミットしたり、Issueにコメントするために必要）。
4. アプリの ⚙ 設定画面で「日程（実際の日付）」と「何分前に知らせるか」を設定したあと、**「📋 GitHub通知用データをコピー」**ボタンを押す。
5. リポジトリの `notify-config.json` を開いて、コピーした内容に丸ごと貼り替え、`git push`（またはGitHub上で直接編集してコミット）する。
6. GitHubの **Actions** タブ → 「配膳お知らせ通知」ワークフロー → 「Run workflow」で手動実行して、エラーが出ないか確認する（この時点で通知対象がなければIssueへのコメントは作られません＝正常）。

### 使い方

- 予定の内容（品目・追加/編集）を変えたときや、日程の日付・通知タイミングを変えたときは、その都度アプリの「📋 GitHub通知用データをコピー」→ `notify-config.json` に貼り替えてpush、を繰り返してください。ここを更新し忘れると、GitHub側の通知は古い内容のまま・または飛びません。
- 「配達完了」にする操作はこのアプリのローカル保存だけの情報なので、GitHub側の通知には反映されません（＝完了済みの予定でも時間になれば通知は飛びます）。通知を止めたい特定の予定がある場合は、`notify-config.json` の `items` からその項目を削除してpushしてください。
- 通知は「配膳お知らせ通知」という1つのIssueへのコメントとしてまとまります。イベント終了後、そのIssueを閉じれば片付きます。
